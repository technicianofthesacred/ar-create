# 12 — Published & complete

Intent agreed 13 October: a useful, rewarding register of ALL requested expressions of a project, not a bare Confirmed label.

## Work surface

Show each requested article, carousel, print/physical article, WeChat article and Twitter/X post with its title/thumbnail, format, language, edition, current status and working destination. Real publication URL/platform/date where published; export file/date/version where exported; explicit missing proof where not known. A carousel may have both downloadable files and a published post link. Physical print can have a print-ready file and separately recorded printing/distribution details if Adrian provides them.

Show remaining work by output and follow-up status alongside completed results. Open live result, retrieve export, continue unfinished variant, view history, approve a correction, begin a new edition, file the project or request another expression from shared origins. Output links must remain tied to the edition that was actually delivered.

## Completion and history

Published date, export date and completion date are different. Save receipts from actual events or clearly attributed human records; never infer publication from a saved file or use today's date to fill missing history. Preserve the original checkpoint12 meaning: applicable feedback/corrections resolved and delivered result/files reconciled. A new edit creates a later edition, preserving the old published one. Completing an article cannot mark its untranslated WeChat version or unfinished carousel complete. Unrequested formats do not become compulsory work.

## Acceptance

Show a project with one live article, one export and one unfinished requested output; every link opens the correct edition and status survives restart. A synthetic previously published output must retain its publication and unsent-feedback distinction. Historical records can lack exact dates; display that honestly. This register is private unless a separate publishing action makes an output public.
