# Stage0 implementation — independent real-material subject

## Goal

S01/S02/S03/S04/S05/S08/S09/S12, C01/C03/C04/C05/C06/C07: open a new real-material test subject in the installed app, with independent working bytes, source lineage and truthful agent attribution; preserve all original HK words, decisions, photos, outputs and shared guidance.

## Architecture

Extend the existing study-draft-copies owner rather than add a manuscript engine. cloneStructureTest accepts one existing source binding, exact saved expected revision, title and operation UUID. It derives a new parent identity and binding, captures the already trusted records without caller paths, and prepares a separate working root using the current raw seed. The owned root is a collection-root with origin structure-test, so existing concept/project discovery and source context can reopen it. Its immutable structureTest provenance identifies the source parent/binding, source draft/capture hashes, creating agent and stand-in role. Original catalog matching must exclude this child.

The server composes this root with existing project/photo/output owners; GET reports exact verified test identity and POST creates/replays the same isolated copy. Agent operations carry agent:codex. The proxy admits only the exact local test-copy operation under existing correction permission, preserving all human-only routes. This stage grants no agent acceptance on originals and no generic bypass; later stand-in review operations must validate this immutable copy authority and record their own decisions under the agent actor.

A small c3Shell decorator reads only structure-test-prefixed subjects and shows a visible compact test/stand-in actor strip without moving/replacing the writer, adding a toolbar, or polling. It refuses stale/foreign metadata.

## Verification and activation

1. Verify immutable ten-record source capture, independent seed/current working bytes, stable parent/binding, replay/restart and no caller-path access with synthetic fixtures outside the installed app.
2. Edit/Undo the synthetic child through the maintained owner; compare original raw/capture/hash/history unchanged. Refuse stale expected values, foreign/original targets, human actor impersonation and corrupt metadata.
3. Verify UI strip attribution, same writer node/unsaved buffer across decoration, no original-page badge, no POST or repeated background reads, and late-response refusal.
4. Before actual copy creation, save original HK Article/native root/Carousel/Direction/shared-guidance/source hashes privately through existing readers. No private data enters Git.
5. Install the exact reviewed candidate using the durable runner. Only then create the authorized real-material copy via its agent-labelled endpoint. Read the copy back, reopen through app discovery and compare all original hashes.
6. Save main screenshots and copy identities privately, update the stage checklist, report the concrete capability and continue Stage1 without asking for author decisions.
